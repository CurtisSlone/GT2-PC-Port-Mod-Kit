Inside GT2's Menus

GT Mode's menus are data, not code. Every screen from the city map to a single tuning part is one page in an archive: a background picture, a layer of label art, and a list of up to 64 rectangles the hand cursor can land on. The title, options, memory card and race menus are a different system, built in code. This page explains both, and what it takes to add new pages and items.

Two kinds of menu

GT2 builds its menus two ways. Which one a screen uses decides how hard it is to change. (GT2 loads its code in parts called overlays, ovl0 to ovl5, from GT2.OVL; the table names the part each menu lives in.)

A page

A page id is simply its member number in the archive. An index file holds the count (3,382) and one offset per member; the game inflates the member and parses it. An id with the top bit set is a message instead, looked up through a small table in solodata.dat.

One page, in file order. The picture is shared between pages that look alike; the label layer belongs to the page alone. The page is loaded during a change, and the picture is read again only when the id differs from the one on screen.

An item: 76 bytes, 19 words

An item is a rectangle in a 512 x 504 menu screen plus what happens when you press on it. Only the first seven words and the last word are ever used. Words 7 to 17 are zero in every item on the disc and nothing reads them.

What the archive holds

Most of the 3,382 pages are tuning parts: one page per part per maker. Labels are pictures

On a GT Mode page almost every word you read is art: printed into the background picture or into the page's label layer, cut into 16 x 8 cells on a grid 32 across and 63 down. Only values that change are drawn as text by the code: credits, days, prices, car names, power figures. That is why an "HP" or "in." next to a number cannot be fixed by changing a string. It is part of a picture.

  • The screen is 512 x 480 interlaced. The background, labels and icons are built into one chain of draw commands at page load and reused every frame.
  • The only highlight of the item under the cursor is the hand switching to its second frame. The item itself does not change.
  • A page change has no fade. For 4 frames nothing new is drawn and the old picture stays on screen while the next page's art is loaded. The only fade is the 12-frame fade to black when GT Mode ends.
  • In the port's remaster look, only the menu-font values are redrawn sharp. The pictures and label art are GT2's pixels, enlarged. Replacing them means new art per picture and per page label layer, not a new font.

A press becomes an action

The cursor snaps to the nearest selectable item in the direction pressed. A confirm press runs the item through four steps in a fixed order. Cancel goes to the page's Back target.

182 codes have code that reads them, and 173 are used on the disc: 68 actions (51 of them the parts slots 20 to 70), 2 lists, 3 dialog buttons, 103 display codes (60 of them license-test trophies), 3 markers and 3 with no behavior. A selection:

Shops and money

Buying works through one "pending operation" record that carries a purchase across pages. A line-up, list, part or wheel item fills it; BUY only checks it; the question page's Yes carries it out. Nothing is written before the Yes, and nothing reaches the memory card until you use Save Game on the title screen.

Limits

  • The garage holds 100 cars. The check happens before the question; Yes does not look again. Prize cars take another path with no message (a prize car can be lost at 100).
  • Prize money is capped at 99,999,999 Cr. Shops only subtract after a check.
  • No other purchase check exists: no region, license or day limit.
  • 50 message ids exist; 8 of them are never shown on the US disc.

The title list and its dispatch

The title menu is a screen-stack menu, not an archive page. Its list has 8 rows, with rows 0 and 7 left blank as spacers, so the cursor is held between 1 and 6. Each row writes one value into a hand-over byte that survives the overlay switch, and the title's entry function acts on it.

ValueRowWhat happens
0Start Gameswitch to overlay ovl4: GT Mode (the city map)

The row labels are images from /arcade/topmenu_panels_<lang>.tim, not strings. A new row (Arcade Mode, for example) needs a ninth table entry, a new value, a case in the dispatch, and either a label image or a row drawn as text. That takes a change to the game's code (the port's Arcade Mode row is such a change).

Adding pages and items

For modders, changes come in two kinds. Data (new pages, new items, events in the race database, dealer cars) can be built as a mod, from your own disc. Code (new actions, title rows, options, more events than the index holds) needs changes to the game's code.

Building a new page

  1. Pick a base page with the right top bar and a close picture. A page shows exactly one picture; pictures cannot be combined.
  2. Edit the items. Keep base items, add new ones, or copy items from other pages and move them.
  3. Edit the label art. Keep cells by region, blank a region with flat color cells, or import cells (with their palettes) from other pages.
  4. Set parent, flags and music. The parent is the Back target; the page's own back button must name the same page.
  5. Link to it from an existing page. New pages are appended after 3,381 with no gaps; the loader rewrites the index.
  6. Check the limits (right) before running it.

Quirks found

Flag 26 does nothing

FOUND

Every line-up car item has flag 26 set. No code in GT Mode reads it.

Car wash price

FOUND

The wash costs 50 Cr in code. The page picture says otherwise (original bug B7 on the bugs page).

A reused message

FOUND

The Wheel Shop refuses 8 car codes with "Your car cannot participate in this race", a message written for events.

Missing car page goes to the map

FOUND

"Car info" looks the car up in the car table; a car code missing from it opens page 0, the city map.

Garage full, checked once

FOUND

BUY refuses at 100 cars. The purchase step checks again, but the Yes button ignores the result.
