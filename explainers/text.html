GT2 Text and Fonts

Where every word and number Gran Turismo 2 prints comes from, how the language setting picks it, the exact time, money and unit formats, and how the fonts place each letter. All of it was checked against the running game.

From a value to glyphs

Every printed number goes the same way: a formatter makes the digits, a string from the language's text block supplies the words and the unit, a layout rule turns characters into x positions, and each character becomes one or two sprites (small rectangles cut from a font picture).

Text blocks: one layout, seven languages

Fixed offsets, no index

Each .txd file holds seven blocks of one size. The game copies the block of the current language to a fixed place in RAM and always looks for each string at the same spot: the speed unit is always race +0x37. A missing translation is an empty string at its offset.

race 5,759 B · title 3,502 · global 1,903 · gt 129 · arcade 736

The language byte

Save byte 0 (1 on this disc) picks the block, the database files (0 Japanese, every other value the usa files), the GT Mode menu folder, the license descriptions, the region filter for cars and the Japanese kanji path. 64 places in the game read it.

copies in RAM at 0x8009229C · 0x80052968 · 0x8002F4C4

Only usa is complete

English misses 160 of 328 race strings and the whole GT Mode block; French, German, Italian and Spanish miss 127 and are damaged (below). The US block is the one complete set of text on this disc.

The damaged European text

The European translators wrote Latin-1 (the Western European character set). Somewhere in the build their files went through a Japanese Shift-JIS to EUC-JP converter, so an accented letter became a lead byte that swallowed the next letter, and letters from 0xA1 to 0xDF became full-width kana. The fonts draw Latin-1, so a French player on this disc would read garbage. The conversion can be undone exactly, except an accent at a string's end, which ate the terminator.

Ré = E9c = 63ord
E9 is a Shift-JIS lead byte: row (0xA9 - 0x81) x 2 + 0x21 = 0x71, column 0x63 - 0x1F = 0x44
RF1C4ord
on the disc: (0x71 | 0x80, 0x44 | 0x80); drawn as "ñÄ". 255 strings turn back into their original text this way.

Units belong to the language's strings; the US game converts power, weight and launch speed for every language. "%d" is the printing pattern for a whole number, "%02d" pads it to two digits.

Fonts and kerning

Sprite fonts (7)

racefont small, medium and large (sizes stored in the game's program, picture in /font/racefont.dat) and four arc_fontinfo fonts. 256 Latin-1 glyphs each; accents are a second sprite drawn over the base letter. Advance = base + width - a pair cut (kerning, the space removed between certain letter pairs) from a bit-packed class table.

Three layouts

Proportional with kerning; tabular digits (each digit centered in a fixed cell so running times hold still); a clock layout with narrow cells for ':' and '.'. Centered = x - width / 2, right = x - width.

GT Mode fonts (2)

A menu font of 267 glyphs (74 ASCII, 119 16-bit codes) and a 24-glyph numeral font, on /arcade/gtmode_font.tim: per glyph an offset and an advance, no kerning. Item flag 31 picks the numerals.

adv(a, b) = base + (w0[a] & 0x3F) - kern[class_left(a)][class_right(b)]
            (a glyph with bit 31 set uses its own fixed cut instead)
width(s)  = sum adv(c_i, c_i+1) + spacing  -  spacing

One detail seen in the running game: during license races, the race reuses the last 48 KB of the arc_fontinfo fonts' memory (those fonts are not used there).
