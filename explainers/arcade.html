GT2 Arcade vs Simulation

GT2's Arcade Disc

Gran Turismo 2 shipped on two discs, Arcade (SCUS-94455) and Simulation (SCUS-94488). Compared file by file and piece of code by piece of code, they turn out to be one program. The Simulation disc already carries the Arcade disc's code and almost all of its data, unused. This page shows what differs, and why physics and AI are the same on both.

The data: the Arcade archive is a subset

Every course, car model, car picture, engine sound, sound bank, the arcade menu art, the attract demos and the arcade database are the same files on both discs. Even the compressed bytes are the same: the shared files were not recompressed. The music file is identical in content.

The Sim-only part is GT Mode's menus (22 entries, 264 MB across 5 languages) plus 261 license demos and rally ghosts. Directory dates suggest the Arcade archive was built about 2.5 hours before the Sim one, on 1999-12-08, from the same set of files.

The code: one program

GT2 keeps a small core of code in memory all the time ("resident") and loads the rest in parts called overlays (ovl0 to ovl5) from GT2.OVL when needed. Both discs load the same overlays at the same addresses. Each piece of code is classed as identical, relocated (the same instructions, but some addresses they point to moved), or really different.

identicalidentical but relocatednear-identical

The Sim disc's unused ovl2 (arcade menus) and ovl3 (arcade race build) are the Arcade disc's arcade code. ovl3 is identical. ovl2 differs in one byte: a pointer to the attract-demo routine, which on the Sim disc correctly points into the Sim title. The Arcade disc's ovl2 would jump 0x20 bytes into the middle of other Sim code, so the Sim disc's copy is the right one to use.

Physics and AI are identical

The race code is 316,776 bytes on both discs and differs in 6 bytes, all inside the two routing places above. The resident code differs in 1 byte (the first overlay after boot). So all the physics and AI, the renderer, HUD, cameras, replays, the car and race database code and the libraries are identical, at the same addresses. There is no separate arcade build with its own constants, assists, damage or AI. What the Arcade game does differently in a race comes from its inputs, which the shared code already handles:

The arcade-only code path

ovl2 is the whole arcade front end (347 routines): its course list and car codes, its strings, and the results and unlock screens. ovl3 is small (16 routines), one of them the race spec builder that also appears twice in GT Mode's code.

Two-player courses are separate, lighter files (2P Rome's geometry is 561,580 bytes against 644,160). Rome Night is its own course file, not a lighting switch. All are on the Sim disc too.

The arcade database

  • 15 events: 12 races (three difficulty rows by classes A, B, C, S, with 8 to 10 opponents each), the two-player battle, and two with no opponents, one of them the time trial.
  • 38 opponent cars.
  • 63 player car set-ups with fixed parts per car, not GT Mode garage tuning. 15 are arcade-only race models with no GT Mode car record; their models are on both discs.
  • The course field reads roma in all 15 events: the course comes from the menu when you pick it.

One save serves both modes. Both programs write the same memory card files with the same layout, and the save already has the arcade fields: options and arcade flags, 32 bytes that look like course clears, two-player wins and course records.

In the port

Because the Simulation disc already holds the arcade code and data, the port's Arcade Mode is a row under Start Game on the title menu that runs the Sim disc's own arcade code, the same way the Arcade disc's Start Game does. The Sim title's idle behavior stays (no intro movie every 4th idle). The only thing the Sim disc cannot supply is the movies in STREAM.DAT (the intro and the two ending credits). The rules for menus, races and unlocks are on the Arcade modes page.
